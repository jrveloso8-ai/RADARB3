exatamente o erro de sequência que a skill de arquitetura de proveniência avisa para
não cometer — e que aqui já se consumou.

N1 · CRÍTICO — Deltas fabricados alimentam a probabilidade de lucro exibida no motor
de estratégias de opções
Arquivo: lib/domain/options-strategy-engine.ts (novo, 54.597 bytes, o maior arquivo de
domínio do projeto)
Padrão repetido em pelo menos 6 pontos: `shortLeg.delta ?? 0.28`, `?? 0.16`, `?? 0.22`,
usados diretamente no cálculo de POP (probabilidade de lucro):
  const shortDelta = Math.abs(shortLeg.delta ?? 0.28);
  const pop = Number(Math.min(0.95, Math.max(0.50, 1 - shortDelta)).toFixed(4));
Quando a perna de opção selecionada não tem delta real vindo da BRAPI, o sistema não
recusa o cálculo — substitui por uma constante e calcula POP normalmente, sem qualquer
rótulo de proveniência distinguindo "delta medido" de "delta assumido". É estrutural e
recorrente, não um descuido isolado: o mesmo padrão aparece para Iron Condor (0,16 nas
duas pernas), Bull/Bear spreads (0,28) e Put de cauda (delta alvo -0,04, que é um
target de busca, não um fallback — esse uso é legítimo). Isso é exatamente o padrão que
a auditoria de 08/09 chamou de "catorze constantes distintas exercendo esse papel" — só
que este arquivo sozinho, criado depois daquela auditoria, já teria contribuído mais
umas 5-6 constantes à lista se tivesse existido então.
Por que importa mais que HV/spot fabricados: aqui a fabricação alimenta diretamente o
número que o usuário usa para decidir se uma trava vale o risco (POP é o número central
de decisão em venda de prêmio) — é uma camada a mais de decisão do que HV, que é
insumo indireto.

N2 · CRÍTICO — Preços de commodities agrícolas fabricados alimentam alvo de preço e
stop-loss de "oportunidades de trade"
Arquivo: lib/domain/agri-commodities.ts (mtime anterior à auditoria de 08/09, mas nunca
auditado — não está em nenhum dos dois laudos anteriores nem no atual até agora)
  const ccmPrice = quotes.ccmPrice || 62.50;   // Milho
  const bgiPrice = quotes.bgiPrice || 242.00;  // Boi Gordo
  const sojaPrice = quotes.sojaPrice || 132.80; // Soja
Diferente de market-quotes.ts, este arquivo NÃO tem nenhum comentário de proveniência,
nenhum campo `source`/`provenance` no objeto retornado, e o preço (real ou fabricado,
indistinguível) alimenta diretamente:
  targetPrice: Number((ccmPrice * 1.08).toFixed(2)),
  stopLoss: Number((ccmPrice * 0.95).toFixed(2)),
Ou seja: se a cotação de milho falhar, o sistema recomenda um alvo de R$ 67,50/saca e
um stop de R$ 59,38/saca — calculados sobre um preço de R$ 62,50 que não existe no
mercado agora, sem qualquer indicação disso na tela. Esta é a área de trabalho central
do usuário (Milho Trader / Agro Intelligence B2B) — é o achado com maior risco de
decisão real de todo este módulo novo, por atingir diretamente o produto que o usuário
constrói para terceiros.

N3 · ALTO — Contagion de proveniência quebrada no radar de oportunidades
Arquivo: lib/domain/opportunity-radar.ts
  const pop = realOptions?.pop ?? 75;
  const convictionScore = Math.min(92, Math.max(65, Math.round(72 + (ivAtm ? ...))));
  ...
  scoreProvenance: 'DERIVADO'   // sempre 'DERIVADO', mesmo quando pop veio do 75 fixo
Este arquivo é o único dos novos que importa `DataProvenance` — ou seja, é o que mais
se esforçou para seguir a cerca estrutural. Mas a regra de contágio que a skill de

ESTIMADO no mínimo), o `convictionScore` que o usa continua rotulado 'DERIVADO' — o
rótulo mais confiável dos cinco. É a versão "com boa intenção, mal executada" do mesmo
problema — pior, em certo sentido, porque o rótulo presente engana mais que a ausência
total de rótulo (o usuário vê "DERIVADO" e confia).

N4 · MÉDIO — Auditor de qualidade do próprio sistema reintroduz o R:R tautológico 1,5
e um ID de estratégia fabricado
Arquivo: lib/domain/study-auditor.ts (o módulo que gera o "selo de auditoria" mostrado
ao usuário — StudyAuditorCard.tsx)
  const strategyId = elected?.strategySpec?.id || 11;
  ...

`11` é o ID real de "Trava de Alta com Call (Bull Call Spread)" em cme-strategies.ts —
não um valor neutro tipo 0 ou null. Quando nenhuma estratégia foi eleita (bloqueada ou
sem match), `strategyId` assume silenciosamente a identidade de uma estratégia

o padrão de gravar um ID de fallback igual a um ID real, em vez de `null` ou um
sentinel dedicado, é o tipo exato de armadilha que já causou o C1/C4/C5 noutros
arquivos. O R:R fixo em 1,5 é a mesma falha já documentada como A11/A12 na auditoria
anterior (em indicators.ts/trade-plan.ts) — agora duplicada aqui, em vez de centralizada
numa função só, confirmando o padrão "thresholds duplicados fora de rules.ts" (M3) já
apontado.
